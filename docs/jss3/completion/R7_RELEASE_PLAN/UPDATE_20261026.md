## 2. Critical ordering finding (observed)
`GET /learning/topics` now ends its query with `ORDER BY COALESCE(t.sequence_rank, t.order_index) …` (`learning.ts:158`) and `POST /learning/topics/:id/complete` selects `sequence_rank` (`:432`); no code referenced the column at `3678e0e`. Deployment never runs migrations (`index.ts:108-113`). On a disposable PostgreSQL 16.15 database loaded with the **pre-Task-05** `schema.sql`, that ORDER BY fails with `ERROR: column t.sequence_rank does not exist`; after only `ALTER TABLE topics ADD COLUMN IF NOT EXISTS sequence_rank NUMERIC(12,6)` it succeeds. The API maps this class of error (42703) to a generic HTTP 500.
**Consequence:** if production auto-deploys from `master` and has not had the new schema applied, the learner topic list and topic-complete routes can already be failing in production. This cannot be checked from here (no production access is authorised, and the repository does not contain the release configuration). **Owner action, read-only:** check the host's deploy history for a deploy of `d8151f4` or later and the live behaviour of the topic list; if affected, the fix is W1 (below), which is a production write and needs owner approval — it is not part of this task.
